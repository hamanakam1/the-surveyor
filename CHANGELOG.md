# Changelog

All notable changes to The Surveyor. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Scheduled services.** A new `services` scanner reads systemd units
  (`systemctl list-units`) and launchd daemons (`launchctl print system`)
  and records them as `workload:` nodes the host runs. The scope is the
  *system* domain on macOS, deliberately: a user session lists an agent for
  every application the operator has open, and those come and go with what
  they are doing. Recording them would make the workload layer churn on
  every scan, which is exactly the noise the tool exists to avoid.
- **`surveyor export` and `surveyor import`**: a plat can cross a ledger
  boundary. A plat is a file, and a file can be shipped — which is the first
  half of the fleet story and the thing that makes the tool composable.
  An import is recorded like any other entry, so the hash chain covers it
  and `surveyor verify` proves it was not edited. It does not disturb this
  host's own history: `HEAD` is still the newest survey *this* host took and
  `HEAD~1` is the previous one, skipping whatever arrived from elsewhere.
  Re-importing the same plat changes nothing, exactly as re-surveying an
  unchanged machine changes nothing. An imported plat is addressable by the
  host it describes: `surveyor show host:shed`.
- **Lint and type checking in CI.** `ruff` and `mypy` now gate every
  change, with the project's own rule set declared in `pyproject.toml`
  rather than inherited from whatever a neighbouring checkout happens to
  configure. `make lint` and `make types` run them locally.
- **A coverage floor.** 80% with branch coverage, enforced in CI. The floor
  is a ratchet: it may only go up.
- **A release workflow.** A tag publishes to PyPI, after checking that the
  tag and `pyproject.toml` agree, that the suite still passes, and that the
  built distribution is well-formed.
- **Storage.** A box whose disk filled up looked unchanged: the host scanner
  reported CPU, memory and thermals, and nothing about where the data lived.
  The scanner now reads `df -P -k` and records the number of filesystems,
  their mount points, and the capacity of the largest one as *facts* — the
  shape of the machine — and the used, free and percentage-full figures as
  *telemetry*, because a disk that fills has not changed, it has merely run
  out of room. Sizes are deliberately **not** summed: an APFS container
  reports the same capacity from five different mounts, and adding them up
  would report five times the disk the machine actually has. The plat says
  so in a warning when it notices a shared container.
- **IPv6, first class.** The network scanner parsed only `inet` records, so
  every IPv6 address, prefix and route was invisible, and an IPv6-only
  interface was dropped as "an interface without an IPv4 address". IPv6
  addresses and prefixes are now parsed on both platforms and emitted as
  `network:` nodes with `family: "ipv6"` and a `scope` of `link-local`,
  `local` or `global`; the IPv6 default route becomes a device node with a
  `routes_via` edge; and an interface with only an IPv6 address is kept.
- **Peer discovery.** The network scanner reads the system's
  address-resolution table (`arp -an` on macOS, `ip neigh show` on Linux) and
  records the neighbours it finds as `device` nodes on the subnet they were
  seen on. A topology map that cannot see the LAN is a map of one machine.
- **A device's identity is its hardware address, not its IP.** The default
  gateway used to be `device:192.168.53.1`, so a DHCP lease renewal produced
  a spurious "device removed, device added" diff on a machine that had not
  changed. A device seen on the wire is now `device:f0-18-98-11-22-33`, which
  survives the lease changing, and is tagged `observed` rather than
  `unverified`. A device that never answered keeps its address-based id and
  the `unverified` tag, because its identity is a guess.
- **An executable schema** (`validation.py`): `surveyor validate` checked two
  things — that no edge dangled, and that the declared fingerprint matched.
  A document with a malformed node kind, an unknown relation, a missing
  field, a bad timestamp, an illegal id, or a nested fact passed. The
  validator now enforces the whole contract, with no dependency, and every
  problem carries a stable code (`unknown-kind`, `dangling-edge`,
  `fingerprint-mismatch`, …) so a CI job can react to the kind of fault
  rather than parse prose.
- **A conformance suite** (`tests/fixtures/invalid/`): one document per
  rule, each broken in exactly one way, with the file name saying which
  way. If a rule stops being enforced, the build stops. The corpus is
  generated by `scripts/make_conformance.py`, so it cannot drift from the
  rules it is meant to describe.
- **A generated schema** (`scripts/make_schema.py`): the committed
  `schema/oet-1.0.schema.json` is built from `surveyor.model`, so the node
  kinds, layers and relations in the schema cannot drift from the ones the
  code uses. A test fails if the committed file is stale.
- **A long-term plan** (`docs/roadmap.md`): four horizons — *Trustworthy*,
  *Complete*, *Fleet*, *Standard* — with the work, the reason, the module it
  lands in, and the evidence that it is done. Includes the sequencing
  dependencies, the explicit non-goals, and the signals that measure
  progress.
- **Screenshots** (`docs/screenshots/*.png`): the survey, the diff, the
  changelog, and the ledger, rendered from live CLI output by
  `scripts/make_screenshots.py`. `make screenshots` regenerates the set;
  nothing in it is hand-drawn.
- **`surveyor redact FILE [--audit]`**: mask a plat's identifiers, and report
  every identifier that survived. The audit distinguishes a declared
  identifier that failed to be removed (a defect) from a value that merely
  looks like one — an email address, a home directory, a long hex digest — and
  exits non-zero so it can gate a publish in CI.
- **A declared inventory of identifiers** (`sensitivity.py`): what counts as
  an identifier is now stated in one reviewable place rather than guessed by
  the redactor, and a scanner that starts emitting a new kind of identifier
  adds a line there.
- **Keyed redaction aliases**: a 256-bit secret in `salt` beside the ledger.
  The same name always produces the same alias within one ledger, so redacting
  twice does not churn the map, and a different alias in every other ledger,
  so two redacted plats cannot be correlated.

### Security

- **The probe boundary resolves programs to absolute paths.** The allowlist
  matched on the program's *basename*, so any path ending in an allowlisted
  name passed, and the inherited `PATH` was passed through unchanged — a
  writable directory earlier in `PATH` could shadow an allowlisted tool.
  Programs are now resolved through a curated search path, and the
  operator's `PATH` is only consulted for directories nobody else can write
  to. A program that resolves into a world-writable directory is refused.
- **The environment scrub list was incomplete.** `AWS_ACCESS_KEY_ID` and
  `SSH_AUTH_SOCK` survived it: the first because no marker matched it, the
  second because `AUTH` was not a marker. The latter handed a child process
  the ability to use the operator's SSH agent. The marker list now includes
  `KEY` and `AUTH`.
- **A probe that overruns is killed, process group and all.** `subprocess`
  killed the direct child only, so a probe that spawned grandchildren could
  leave them running after the timeout. Probes now start in their own
  session and the whole group is killed on timeout.
- **The allowlist is least privilege.** Eight programs were allowlisted with
  no caller — `arp`, `df`, `launchctl`, `netstat`, `nvidia-smi`,
  `powermetrics`, `system_profiler`, `uptime`. An allowlisted program is an
  attack surface, so the list now holds only what a scanner actually runs, and
  a test fails if an allowlisted program has no caller.
- **`--redact` no longer leaks the identifiers it claimed to remove.** The
  old redactor masked MAC addresses and serials and left everything else in
  the clear. A redacted plat still carried:
  - the **hostname**, in node ids (`host:studio`), in labels, in
    `facts["hostname"]`, and in `observations["hostname"]`;
  - **container names**, in node ids, labels, and the `workload` fact of every
    service they publish;
  - **model names**, in node ids and labels;
  - **listener process names**, in service facts and labels;
  - **every edge fact**, which were copied without redaction at all;
  - MAC addresses in the dash form, and IPv6, which was never parsed.

  Redaction now aliases names throughout the document — including node ids,
  with edges rewritten to match, so a redacted plat has no dangling edges and
  the same graph — masks dash-form MACs, and truncates globally routable IPv6
  addresses. The policy is documented in `docs/oet-1.0.md` §8 and in
  `SECURITY.md`.
- **Aliases are keyed.** An unkeyed digest of a hostname or container name can
  be reversed by hashing a word list, which made the old redaction a speed
  bump rather than a protection. Aliases are now
  `sha256(salt + slug(value))` against a per-ledger secret.

### Changed

- **The ASCII map shows the hubs first.** A modern edge box has hundreds of
  scheduled services and a handful of things that actually matter, and a map
  that shows the first six alphabetically showed the reader neither. Nodes
  are now ordered by how many relationships they take part in, so the model
  server that serves eight models comes before the daemons that merely
  exist, and the edge list is ordered the same way. A truncated layer also
  says what it left out — `440 launchd · 8 model · 1 ollama · 4 service`.

### Fixed

- **A discharging battery was reported as charging.** The power parser
  tested `"charging" in detail` before `"discharging" in detail`, and
  *discharging* contains *charging* — so every battery running down the
  hill said it was charging. The more specific state is now tested first.
- **Long names could collide into one node.** `util.slug()` truncated at
  eighty characters with nothing to distinguish the result, so two container
  names that shared their first eighty characters produced the same node id
  and the second observation silently overwrote the first. The truncation now
  carries a short digest of the original, which is stable, so ids do not
  churn between surveys.
- **The scribe can no longer contradict its own changelog.** A diff whose
  changes were all `notice`-level — a container, a model, a socket appearing
  — produced an empty narrative and fell through to *"Only the weather
  changed: 1 telemetry series drifted."* while the changelog body underneath
  listed the structural changes in full. The narrative now partitions
  structural changes by polarity, names node changes before edge changes,
  ranks by significance (`host` > `power` > `workload` > `model` > `service` >
  network kinds), and only reports weather when there is genuinely nothing
  structural to report.
- **Edge changes are no longer filed under "Unaligned".** An edge change
  inherited no layer, so every one of them grouped into a separate heading
  that meant nothing. An edge now belongs to the layer of the node that
  initiates it.

## [Unreleased]

### Added

- **Outbound notifications** (`notify.py`): a structural change can now reach
  Slack, Discord, Mattermost, ntfy, or any endpoint that accepts JSON.
  - `--notify URL` (repeatable), `--notify-on critical|warning|notice|never`,
    and `--no-notify` to silence one run.
  - `notify`, `notify_on`, `notify_format`, `notify_timeout` in the config;
    `SURVEYOR_NOTIFY` and `SURVEYOR_NOTIFY_ON` in the environment.
  - `surveyor notify` sends a test ping; `--dry-run` prints the payload
    instead of sending it.
  - Severity gating matches the diff ladder, so telemetry drift never pages
    anyone. A failed delivery is reported, never raised -- a dead webhook
    cannot stop a survey or a daemon.
  - Webhook URLs are masked in every message, log line and error, because a
    webhook URL is a bearer token.

## [1.0.0] — 2026-10-22

The scaffold becomes software. Everything below is new; the previous state of
this repository was a README describing the intent.

### Added

- **OET 1.0 object model** (`model.py`): four layers, nine node kinds, nine
  relations, and a hard split between structural `facts` and drifting
  `telemetry`. Structural fingerprint and content digest are separate identities.
- **Four scanners**, each independently failable:
  - `power` — `pmset`/IOKit on macOS, `/sys/class/power_supply` on Linux,
    including battery chemistry, design capacity, charge, cycle count.
  - `host` — CPU, memory, board model, kernel, boot mode, load, thermals.
  - `network` — interfaces, MACs, IPv4 subnets, default gateway, Wi-Fi SSID,
    with loopback and tunnel interfaces excluded by default.
  - `workloads` — Docker containers, a local Ollama server with its models, and
    externally reachable listening sockets.
- **Read-only probe layer** (`probe.py`): command allowlist, argument vectors
  only (never a shell), scrubbed environment, empty stdin, hard timeouts.
- **Compiler** with concurrent fan-out, a total time budget, duplicate merging,
  dangling-edge pruning, and per-scanner observation records.
- **Severity-classified differ**: `critical`, `warning`, `notice`, `info`, with
  telemetry drift explicitly non-structural.
- **Scribe**: deterministic Markdown changelogs, plus optional Ollama rewrite of
  the opening paragraph only, with graceful fallback.
- **Ledger**: content-addressed objects (name == SHA-256 of canonical bytes),
  append-only journal, parent-linked hash chain, HEAD pointer, writer lock, and
  `verify` that catches tampering, reordering, and missing objects.
- **Idempotent commits**: an unchanged structural fingerprint writes nothing.
- **Redaction** for publishable plats: MAC vendor prefixes kept, serials and
  SSIDs aliased, public IPv4 truncated, private addresses preserved.
- **Daemon** with interval cadence, single-instance lock, and clean SIGINT and
  SIGTERM handling.
- **Rendering**: layered ASCII plat, Markdown tables, and a Mermaid graph.
- **CLI**: `scan`, `diff`, `log`, `show`, `verify`, `daemon`, `scanners`,
  `init`, `validate`, `banner`, with `--json`, `--redact`, `--output`,
  `--exit-code` (3 = structure changed), and `--no-save`.
- **Configuration**: TOML (default), JSON, optional YAML, environment overrides,
  and a `surveyor init` writer. Zero runtime dependencies.
- **Documentation**: the OET 1.0 specification, a JSON Schema, an architecture
  note covering the failure model and ledger internals, a sample plat, example
  config, systemd and launchd units, and CI on macOS and Linux.
- **A new banner.** The old block-letter wordmark is replaced by a levelled
  theodolite on a tripod, sighting a four-node graph: *plat no. 007, not to
  scale*.

### Changed

- README rewritten around what the software actually does, with real output,
  the core loop, and the guarantees (read-only, idempotent, verifiable).
- Field parsers are pure functions so they can be tested without a host.

### Fixed

- Fingerprints are independent of edge insertion order; previously a document
  could fail its own validation after a round trip.
- Scanner bootstrap no longer hides built-ins when a single scanner module is
  imported first.
